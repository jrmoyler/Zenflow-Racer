# P0.11 — full visual QA across all twenty racers

Generated by `node tools/p0-webgl-qa.cjs` from the shipping `index.html`, running in a real
browser against a **real WebGL context**. Every image in this directory is a frame the
game's own renderer drew, through its own materials, tone mapping, shadow map and post
chain — not a CPU contact sheet, and not a mock.

| | |
|---|---|
| Renderer | `ANGLE (Google, Vulkan 1.3.0 (SwiftShader Device (Subzero)), SwiftShader driver)` |
| Racers | 20 |
| Views per racer | 11 — front, rear, left, right, hero, cockpit, chase, drift, boost, victory, hit |
| Console / page errors | **0** |
| QA issues | **0** |

Raw measurements for every racer and view: `report.json`.

## What this establishes, and what it does not

**It does** show that all twenty racers load, rig, animate and render through the real
WebGL path without an error, a missing material, a detached part, a hand off its grip or a
frame that failed to draw — and it shows what each one actually looks like when drawn.

**It does not** establish art direction. Nobody has approved how these look; that is a
human judgement and it is still outstanding. It also says **nothing about performance on a
phone**: SwiftShader is a software rasteriser running on a container CPU, so its frame
times are meaningless as device evidence. P0.12 physical-device certification remains open
and is not addressed here in any form.

## Measured results

### Per-racer rendering

Measured on the hero view across all twenty racers:

| | min | mean | max |
|---|---:|---:|---:|
| Triangles | 54,361 | 73,157 | 92,793 |
| Draw calls | 92 | 102 | 169 |
| Meshes | 92 | 102 | 169 |

Every frame drew: sampled distinct colours range from 168 to 648 per view, and mean
luminance from 165.3 to 225.4. No frame came back blank or uniform.

**All eleven views of all twenty racers produced eleven distinct rendered frames.** That
matters more than it sounds: it is direct evidence that the drift, boost, victory and hit
clips really applied to the geometry the renderer drew, rather than the harness quietly
rendering the same pose eleven times.

### The QA checklist

| P0.11 check | How it was checked | Result |
|---|---|---|
| no missing material | every mesh's material inspected on the live object | 0 across 220 captures |
| no detached limbs | every rider mesh must sit inside the pilot envelope, and the pilot inside the chassis envelope | 0 outside |
| hands aligned | each glove measured against its own grip point in steering-wheel space | **max gap 0.000 m** across all racers and views |
| wheels aligned | four pivots, matched heights, mirrored track | 4/4, height spread 0.000 m, track spread 0.000 m |
| steering pivots correct | wheel and steering-wheel transforms finite and mirrored | no non-finite world matrices |
| no duplicated rider parts | named-node census for torso, head, identity marker, steering wheel | none duplicated |
| no broken glow | emissive surfaces still present after material work | present on every racer |
| no broken shadow | shadow map state recorded per profile | on for desktop, off on the reduced paths |
| no broken mobile fallback path | emulated handset and `lowfx` profiles booted and rendered | see below |
| no clipping, no z-fighting, no bad LOD/pop, no inverted normals, no floating panels, no skin/cloth crossover | **not automated** — these are judgements about how a frame looks | the sheets are provided for a human to make them |

The last row is deliberate. Those are the checks that need eyes, and claiming a tool had
made them would be the fabrication this pass exists to avoid. What the tool guarantees is
that a human reviewing the sheets is looking at what the real renderer produced.

Note on the released poses: the celebration deliberately releases the right hand and the
spinout releases both, so those are excluded from the hand-to-grip measurement rather than
counted as gaps. That exclusion follows the rig's own rule in `constrainKartHands`.

### Garage and reward screens

The Garage opened through its own button on a fresh save: 25 cards, 24 of them locked, each
locked card carrying its shortfall note, with the live kart preview rendering. The reward
screen was captured from the staged podium fixture, which never writes a record or claims a
completed race — the summary reads `Saving race rewards…` because the capture caught the
transaction mid-flight.

## Reproducing

```
node tools/p0-webgl-qa.cjs                       # everything, ~50 min under SwiftShader
node tools/p0-webgl-qa.cjs --only race,screens   # re-run selected phases, merging the report
```

Needs Playwright and a Chromium build. The tool refuses to run without them rather than
inventing screenshots.
